# U10 — Log views: script-with-line-number errors link to the editor at that line ✅ implemented
*Archived roadmap item — Web UI & Editor. Open items: [../../ROADMAP.md](../../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Implemented.** Script locations in log messages — the label prefix (`licht/hobbyraum.js: …`) and stack-frame positions (`…/scripts/licht/hobbyraum.js:12:5`) — are links in both the Logs tab and the Scripts tab log panel. Clicking opens the script in the editor and, when a line number is present, places the Monaco cursor there (`revealLineInCenter` + `setPosition` + focus).

**Shipped:**

- `web/src/lib/log-links.ts` — shared segmentation: `splitLogMessage()` splits a message into text/link segments; a `.js` token (optional `:line[:col]`) only becomes a link when it resolves to a known script — exactly or as a **path suffix**, because stack frames carry the absolute vm filename while the script tree uses relative paths. Unknown paths (node internals) stay plain text. `scriptResolver()` + `collectScriptPaths()` build the resolver from a scripts tree.
- `Logs.svelte` — fetches the script tree once for the resolver; renders segments; links dispatch the `she:open-script` event (from U8), now with optional `line`/`column`, after switching the hash to the Scripts tab. This supersedes U8's prefix-only linking.
- `Scripts.svelte` — resolver derived from its live file tree; the log panel renders the same segments; the `she:open-script` handler and panel clicks go through a new `openAtLine()` (openTab → reveal/position/focus).

**Line-number accuracy:** guaranteed by she's no-wrapper script compilation (`vm.Script` with the file as `filename`; the D1 async-IIFE rejection preserved this) — stack line numbers match the on-disk file.
