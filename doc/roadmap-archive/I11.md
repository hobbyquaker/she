# I11 — Services: remove she from a host (disconnect / teardown) ✅ implemented
*Archived roadmap item — Integrations. Open items: [../../ROADMAP.md](../../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Implemented (she 1.30.0), filed and built in one step.** The counterpart of the setup command ([I9](I9.md)): she can take herself off a host again — needed when a test instance hands hosts over to a production one, and generally so that nothing the bootstrap created is left without a way back.

- **Why two degrees.** The setup script *appends* she's key to `authorized_keys`, so running a second instance's setup on a host leaves the first instance with root-equivalent access through the sudo rule. *Disconnect* removes exactly that: this she's key, nothing else (the other instance keeps working). *Remove everything* also removes the sudoers rule, the helper and the `she-services` user with its home; it refuses while other keys remain in that user's `authorized_keys` (exit 3 → `OTHER_KEYS`) unless forced, so one instance cannot silently cut off another.
- **Helper v6** ([service/she-servicectl](../../service/she-servicectl)): `remove-key` (public key on stdin; the affected account is the sudo caller — `she-services`, or root on hosts she reaches as root — matched by key material, so comments and option prefixes do not matter; owner/mode of the file kept) and `teardown [--force]` (key, then every `/etc/sudoers.d` file that mentions the helper — deleted when it allows nothing else, otherwise just the helper line, which is what happens on the she host with `/etc/sudoers.d/she`; then `userdel -r -f she-services` only when she logs in as that account; then the script and its `.bak`, last). Adapters, instances, units, env files and `broker.env` are untouched by design.
- **API** ([src/web/services-api.js](../../src/web/services-api.js)): `POST /hosts/:host/helper/remove { mode, force? }` — sends the public key of the host's SSH identity (the services key, or the entry's `identityFile`), runs the helper, then drops the host entry from config.json and invalidates the hosts cache. The she host only supports `all` (no key to remove).
- **UI**: one panel component ([RemoveHelper.svelte](../../web/src/pages/services/RemoveHelper.svelte)) used by *Remove…* in Services → Hosts and *Remove from host…* on the host cards in Settings → Services: two radio choices with what each removes and what stays, *Remove everything anyway* after an `OTHER_KEYS` refusal, the host list reloads afterwards.
- Docs: [doc/services.md](../../doc/services.md) (Remote hosts → Removing a host, helper command list), [doc/http-api.md](../../doc/http-api.md), [doc/security.md](../../doc/security.md). Tests: fake helper `remove-key`/`teardown` (`FAKE_OTHER_KEYS`), route tests for key mode, refusal + force, the local host, and a host without a key.
