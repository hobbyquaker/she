# B6 — matter.js logs recurring "FATAL Unhandled error detected: {}" — say what actually failed ✅ fixed
*Archived roadmap item — Bugs. Open items: [../../ROADMAP.md](../../ROADMAP.md) · Index: [README.md](README.md)*

**Reported (08/2026).** The Logs tab repeatedly showed `matter.js: … FATAL Unhandled Unhandled error detected: {}` — no error class, message, or location.

**Cause.** matter.js's unhandled-error catcher (`Logger.reportUnhandledError`) logs the bare thrown value; a non-`Error` throwable renders as `{}` in the PLAIN diagnostic format, and `Error#cause` / `AggregateError#errors` details are dropped. The line reached she through the Logger destination bridge in `src/matter/controller.js`.

**Fix (three layers in the bridge):**

1. **`Logger.reportUnhandledError` replaced** (the hook is explicitly designed to be replaceable): unhandled errors are now rendered with Node's `util.inspect` (depth-limited, cycle-safe — includes stacks, `cause`, aggregate errors, and non-Error object properties) and logged as `matter.js: unhandled error: …`.
2. **Enrichment for other uninformative error lines**: when a formatted error-level line ends in `{}` / `[object …]`, the structured `Diagnostic.Message.values` are inspected and appended, recovering the detail the formatter discarded.
3. **Rate-limiting**: identical repeating error lines (the reported case repeated continuously — typical for a failing reconnect loop) are suppressed within a 30 s window with a heartbeat every 20th occurrence and a "repeated N more times" summary when a different line arrives.

Also: matter.js's embedded timestamp is stripped from bridged lines — the Logs tab adds its own.

**Follow-up:** with real details now visible, identify what the recurring error actually is (correlate with device online/offline transitions); file as its own item once known.

**Tests:** `matter-controller.test.js` — enrichment from message values + timestamp stripping + repeat suppression + summary flush; `reportUnhandledError` detail for non-Error throwables.
