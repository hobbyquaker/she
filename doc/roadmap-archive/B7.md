# B7 — Scripts tab: clicking a script does nothing, "Model is disposed!" in the console ✅ fixed
*Archived roadmap item — Bugs. Open items: [../../ROADMAP.md](../../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Fixed (she 1.28.1).** Reported on a 1.21.1 instance: opening a script from the tree did nothing; the console showed `Uncaught (in promise) Model is disposed!` from `editor.setModel()`.

**Cause:** `openTabInternal()` created the Monaco model for a file, then *awaited* the daemon log history (`getHistoryEntries()`, slow on a large `she.jsonl`) before adding the tab to `tabs`. A second open of the same file inside that window — typically the click on a script while the tabs persisted from the last session were still being restored on page load — found no tab yet, ran `monaco.editor.getModel(uri)?.dispose()` and thereby disposed the first call's model; the first call then stored the dead model and `switchTab()` handed it to `setModel()`. The disposed tab stayed first in `tabs`, so every later click failed the same way until reload.

**Fix** ([web/src/pages/Scripts.svelte](../../web/src/pages/Scripts.svelte)): opens are de-duplicated per path while in flight (both callers await the same promise); an existing, live model for the URI is reused (`setValue` when the content differs) instead of being disposed and recreated; `switchTab()` recreates a disposed model from the tab's saved content instead of crashing the click handler.

**Relates:** [U5](../../ROADMAP.md#u5--file-tree-virtualization) (tree), the tab persistence that triggers the restore.
