# I9 — Services: remote host bootstrap script ✅ implemented
*Archived roadmap item — Integrations. Open items: [../../ROADMAP.md](../../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Implemented (she 1.24.0), filed and built in one step.** One command, run as root on a remote host, prepares it for the Services page:

```
curl -fsSL 'http://she:8080/she/services/setup.sh?token=…' | sudo bash
```

- **Backend** ([src/web/services-api.js](../../src/web/services-api.js)): `POST /she/services/setup/token { origin }` mints a 24-byte one-time token (15 min), generates the services SSH key on demand, renders the script and returns `command`, `scriptUrl`, `sha256`; `GET /she/services/setup.sh?token=` (unauthenticated, exempted in `server.js`) serves the script exactly once; `POST /she/services/setup/done?token=` (unauthenticated) is the callback — it adds `{ hostname, ssh: { host: <caller address>, user: "she-services" } }` to `services.hosts` (or updates an existing entry for that address/hostname), invalidates the host cache and burns the token; `GET /she/services/setup/token/:token` reports `pending | fetched | done | expired` for the UI.
- **Script** (`buildSetupScript()`, POSIX sh, idempotent): requires root; creates the system user `she-services` (home, `/bin/sh`); appends she's public key to its `authorized_keys`; installs the embedded `she-servicectl` (heredoc with a quoted delimiter — the generator refuses a helper that contains it); writes `/etc/sudoers.d/she-services` with the single rule, `visudo -c`-checked; posts hostname + user back with curl or wget; prints what it did.
- **Frontend** (Settings → Services → *Set up a remote host*): origin field (defaults to the browser's), *Create setup command*, the command with *Copy*, sha256 and the download alternative, live state (waiting → fetched → registered) polled every 3 s; on *done* the host list is re-read from `config.json` so a later Save keeps the new entry. Hosts-tab hints point to it.
- **Tests**: token lifecycle (400 without origin, script once, sha256 match, callback adds the host, second callback 410, re-run updates instead of duplicating, unknown token 410, delimiter guard).
- **Docs**: services.md *Remote hosts* rewritten around the command, HTTP API rows, security.md paragraph on the two unauthenticated routes and the plain-HTTP caveat.

**Design (from the discussion that led here):** the manual path (copy key, deploy helper, add sudoers line) pushed users towards ssh-as-root; the bootstrap makes the least-privilege setup (dedicated user, one sudo rule — SV-4) the default and removes three manual steps. Decisions: the endpoint is public but useless without a short-lived single-use token; the script embeds everything (no run-time downloads) and its sha256 is shown for inspection; user name `she-services` (not `she`, to avoid clashing with a she installation on the same host); the callback's source address becomes the ssh host and is editable. *Deploy helper* remains the path for hosts with existing SSH access.
