# B8 — `SHE_*` environment variables were documented but never read ✅ fixed
*Archived roadmap item — Bugs. Open items: [../../ROADMAP.md](../../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Fixed (she 1.37.0).** [cli.md](../../doc/cli.md#environment-variables) has always stated *"Every option can be provided as an environment variable with the `SHE_` prefix"* and listed fifteen of them, but [src/config.js](../../src/config.js) never called yargs' `.env()`. `SHE_PORT=1234 she` silently started on 8080. Only `SHE_DATA_DIR` and `SHE_SECRETS_KEY` worked, because those two are read straight from `process.env` by [storage.js](../../src/lib/storage.js) and [secrets.js](../../src/lib/secrets.js). Found on 2026-08-28 while documenting the safe-mode options ([S4](S4.md)).

**The fix is one line — `.env('SHE_')` — plus two things that line exposes:**

- **The prefix needs its trailing underscore.** yargs-parser matches the prefix as a plain string (`envVar.lastIndexOf(prefix, 0) === 0`) and then slices `prefix.length` off the front. With `.env('SHE')`, `SHELL` — set in every shell on earth — matches and lands in the config as `ll: '/bin/zsh'`. `.env('SHE_')` does not match it.
- **`SHE_SECRETS_KEY` is not an option** but does match the prefix, so it arrived as `config.secretsKey` — and the config object is `log.debug`-ed at startup, which would print the secrets master key into the log file and the log WebSocket. It is deleted right after parsing, with a comment saying why.

**Second bug, uncovered by the first.** Fifteen keys were declared as bare `.default({ … })` entries rather than typed `.option()`s. Without a declared type, a value coming from the environment stays a **string** — so `SHE_DISABLE_WATCH=false` would have been the truthy string `"false"` and silently *disabled* file watching, and `SHE_LATITUDE=52.52` would have been `'52.52'`. They are now typed options with `describe` text, so they also show up in `she --help` for the first time (they were already documented in cli.md as CLI flags). Behaviour for CLI flags and config-file values is unchanged.

**Precedence** is now what [cli.md](../../doc/cli.md#precedence) always claimed, verified in both directions: CLI flag > env var > config file > built-in default.

Tests: [test/unit/config.test.js](../../test/unit/config.test.js) — 7 cases covering coercion, the precedence chain, the `SHE_SECRETS_KEY` exclusion and the `SHELL` collision.

**Also fixed in passing:** the "no MQTT broker URL configured" warning pointed at `~/.she/config.json` regardless of `--data-dir` / `--config`; it now names the file actually in use.
