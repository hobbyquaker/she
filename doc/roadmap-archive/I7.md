# I7 — Services: adapter catalog via npm ✅ implemented
*Archived roadmap item — Integrations. Open items: [../../ROADMAP.md](../../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Implemented (she 1.27.0).** The *Catalog* tab lists the adapters that can be installed and installs them on a host.

**Membership rule changed from the plan** (decided in discussion before building): no keyword, no field, no catalog file — *depending on `mqtt-interfaces-core`* is the criterion. The npm registry has no official dependents API, so she turns it around: for every publisher in `services.trustedPublishers` (default `hobbyquaker`) one registry search (`maintainer:<user>`), then the abbreviated packument of each hit (`application/vnd.npm.install-v1+json`) to check whether the latest version depends on the core, then the full packument for the members only (description, homepage, repository, the optional `mqttInterfaces` field with `needs`/`serviceExtra`). Deprecated packages are skipped. Cached 24 h with the last good list kept (marked *stale*) when the registry is unreachable; per-publisher failures are reported without hiding the rest. The trusted-publishers list is the install gate: `install-package` refuses anything else (403 `NOT_IN_CATALOG`). Third-party adapters are added by trusting their publisher — the explicit decision the user would have to make before installing anyway.

- **Backend**: [src/lib/services-catalog.js](../../src/lib/services-catalog.js) (`catalog()`, `sweep()`, injectable fetch), `GET /she/services/catalog[?refresh=1]`, `POST /hosts/:host/adapters/:adapter/install-package` (helper `npm <adapter> install`, host cache invalidated).
- **Frontend**: `services/Catalog.svelte` (filter, refresh, stale/error notes, per package: version, date, publisher, prerequisites badge, docs link, installed-on with update hint, host select + Install/Update, npm output), *Trusted publishers* field in Settings → Services, the Add-instance wizard points to the Catalog when a host has no adapters.
- **Tests**: catalog module against a fake registry (membership, deprecated, publishers, cache/refresh, partial failure, stale fallback); route tests (listing, install gate).
- **Docs**: services.md (Catalog paragraph, config row), http-api rows, security note; the core README's "fleet membership" section now states the dependency rule and makes `mqttInterfaces` optional metadata.

**Original item:**

No catalog file: adapters mark themselves with the npm keyword `mqtt-interfaces` and a `mqttInterfaces` package.json field (spec, envPrefix, serviceExtra, needs). she searches the registry (24 h cache, last-good fallback, exact-keyword filter, deprecated skipped), reads metadata from the packument, and gates *Install* by `services.trustedPublishers` (default `hobbyquaker`; others listed as unverified). Install-from-catalog feeds the Add-instance wizard. Needs the adapters republished with keyword + field (documented in the core README). Depends on [I4](doc/roadmap-archive/I4.md) ✅.
