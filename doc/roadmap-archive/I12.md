# I12 — Memory and CPU per instance ✅ implemented
*Archived roadmap item — Integrations. Open items: [../../ROADMAP.md](../../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Implemented (she 1.36.0, mqtt-interfaces-core 0.8.0), filed and built in one step** after the user went with the two-source recommendation.

- **Source A — the adapter** (portable, primary): the core publishes `<name>/maintenance/stats` (retained) every `--stats-interval` seconds (default 60, 0 = off): `rss`, `heapUsed`, `heapTotal`, `cpu` (percent of one core over the interval, from `process.cpuUsage()` deltas), `eventLoopLag` (worst lateness of a 1 s timer in the interval), `uptime`, `ts`. `maintenance/` is the namespace the convention already uses; `info` stays static. Works for every host — remote, Docker, unmanaged. Adapters pick it up with a dependency bump to `^0.8.0`.
- **Source B — the host** (fallback): helper v10's `list` adds `pid`, `memory` (systemd `MemoryCurrent`) and `cpuNs` (`CPUUsageNSec`) per instance; the daemon keeps the last sample per host + unit and derives `cpu` (share of one core) between two listings (`null` on the first).
- **she**: [services-inventory.js](../../src/lib/services-inventory.js) parses `<instance>/maintenance/stats` into `stats` (only while connected); the Instances tab shows *Mem* and *CPU* columns, adapter stats first, systemd second, the tooltip naming the source.
