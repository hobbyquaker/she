# M9 — Script start waits for the Matter controller ✅ implemented
*Archived roadmap item — MQTT, Matter & Broker. Open items: [../../ROADMAP.md](../../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Implemented (user-requested).** Scripts calling `she.matter.*` at top level failed on daemon startup with `Error: Matter controller not started` — script loading was gated only on the MQTT retained-state sentinel, while the Matter controller initialized concurrently.

**Shipped:** script start in `src/index.js` now waits on **two gates**: MQTT retained state (the existing sentinel flow, incl. its timeouts) and — when `matterStorage` is configured — Matter controller startup. The matter gate is pre-opened when the controller is disabled, opens on init completion (success *or* failure — a broken controller must not block the script engine; matter calls then fail with their own clear error), and has a 30 s safety timeout ("matter controller not ready after 30s — starting scripts anyway"). The no-broker startup path (`config.url` empty) also goes through the gate logic now instead of starting scripts directly.

**Deviation from the request:** the suggested "only wait when at least 1 device is paired" condition was dropped — the wait decision must be made before the controller has loaded its peers, and waiting for init costs practically nothing when no devices are paired (controller start is fast; the 30 s cap covers pathological cases). Waiting whenever Matter is enabled is simpler and behaviorally equivalent.

**Verified:** unit suite (260) green; integration startup-flow tests (sentinel, script loading, no-matter path) green — the one flaky shedb timeout also fails without this change.
