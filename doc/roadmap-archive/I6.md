# I6 — Services: broker.env and per-instance dynsec credentials ✅ implemented
*Archived roadmap item — Integrations. Open items: [../../ROADMAP.md](../../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Implemented (she 1.25.0).** Both halves shipped, the first in a simpler form than planned:

- **Broker settings per instance instead of a managed `broker.env`** (shipped with I5, 1.24.0): the instance config form and the Add-instance wizard carry a *Broker credentials* choice. *she's settings* writes she's own MQTT URL/username/password into the instance's env file (loopback rewritten to she's hostname for remote hosts) and re-applies them on every save (`SHE_USE_BROKER=1`). `/etc/mqtt-interfaces/broker.env` stays a core convention she does not touch — the automatic generation tried in between was dropped as unintuitive.
- **Dedicated dynsec identity** (this release): mode *dedicated identity* creates a dynsec role and client `svc-<instance>` (random 18-byte password) whose ACL allows only `publishClientSend`/`publishClientReceive`/`subscribePattern`/`unsubscribePattern` on `<instance>/#` plus `publishClientSend` on `homeassistant/#` (discovery); the ACL is shown before saving and can be overridden per request. The credentials go into the instance env with `SHE_DYNSEC_CLIENT=svc-<instance>`; *Rotate password* re-keys the client and restarts; switching the mode or uninstalling the instance deletes client and role. Available only while the dynsec admin connection is ready (Mosquitto management); otherwise the option is disabled with a hint.

Files: [src/web/services-api.js](../../src/web/services-api.js) (`applyBrokerMode()`, `createInstanceCredentials()`, `defaultAcl()`, `brokerMode`/`acl`/`rotate` on the env and install routes, cleanup on uninstall; reuses [src/lib/dynsec.js](../../src/lib/dynsec.js)), `SchemaForm.svelte` (three-way radio + ACL preview), `InstanceDetail.svelte` (*Rotate password*), `AddInstance.svelte`; tests with a dynsec mock (`setDynsec()`); docs in services.md, http-api.md, security.md.
