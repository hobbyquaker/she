# B2 — Cleared retained topics linger in the state store / MQTT tab ✅ fixed
*Archived roadmap item — Bugs. Open items: [../../ROADMAP.md](../../ROADMAP.md) · Index: [README.md](README.md)*

**Reported (08/2026).** "Clear retained" in the MQTT tab (recursive) published empty retained payloads and the broker cleared them (verified via `mosquitto_sub`), but the topics stayed visible in the MQTT tab until a daemon restart.

**Root cause.** she had no handling for the empty-payload deletion convention: an empty payload was parsed to `{ val: NaN }` (via `parseFloat('')`) and stored, so the state store — the source of `GET /she/mqtt/state` and the MQTT tab — kept the topic forever. An important subtlety found during the fix: **the retain flag cannot be used to detect a retained-clear** — MQTT 3.1.1 brokers clear the RETAIN flag when forwarding to established subscriptions, so she (subscribed to `#` the whole time) receives the clear as a plain empty message. The fix therefore treats *any* zero-length payload as deletion, which is also the mqtt-smarthome ecosystem convention she descends from.

**Fix.**

- `src/index.js` message handler: a zero-length payload deletes `mqtt::<topic>` from the state store (and `var::<name>` for `<variablePrefix>/status/<name>` topics) instead of storing `NaN`. Subscription callbacks are **still dispatched** (empty publishes are widely used as plain triggers — the `she.global` integration test relies on it) with `val: ''`; only the stored state is dropped.
- `src/lib/state-store.js`: new `delete(key)` → emits `'delete' (key, prevObj)`, returns whether the key existed.
- `src/web/mqtt-api.js`: forwards deletions to WS clients as `{ type: 'mqtt', topic, deleted: true, ts }`; the `/she/mqtt/state` snapshot reflects deletions automatically.
- `web/src/pages/MQTT.svelte`: handles `deleted` — drops the topic from `topicMap`/`liveTopics`, un-leafs and prunes the topic tree (`removeNode()`), bumps the render version.
- `src/lib/redis.js`: `'delete'` → `HDEL she:state <key>` so the write-through cache doesn't resurrect cleared topics on restart.
- Docs: empty-payload semantics documented at `she.mqtt.get()` in `doc/sandbox-api.md`.

**Behaviour change (documented):** empty payloads no longer produce a `{ val: NaN }` state entry; callbacks now receive `''` instead of `NaN`.

**Tests:** `state-store.test.js` (delete semantics + event), `redis.test.js` (hdel write-through), `integration.test.js` (publish retained → clear with empty retained → store removal log line; the existing `she.global` test covers callbacks still firing on empty-payload triggers).
