# I2 — InfluxDB v1 compatibility ✅ implemented
*Archived roadmap item — Integrations. Open items: [../../ROADMAP.md](../../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Implemented.** `src/influx.js` now supports two modes: **v2** (`url`/`token`/`org`/`bucket` → `@influxdata/influxdb-client`, Flux) and **v1** (`url`/`database` + optional `username`/`password`/`retentionPolicy` → the classic 1.x HTTP API: line protocol via `POST /write?db=…&precision=ms`, InfluxQL via `GET /query?db=…&epoch=ms`, Basic auth). The mode is inferred from the config keys (`database` → v1, `token` → v2) and can be forced with `version: 1`. No new dependency — the v1 transport uses global `fetch` with a 10 s timeout.

The whole `she.influx.*` sandbox API works in both modes: `query()` takes InfluxQL in v1 mode (rows flattened to plain objects with series tags merged and `_measurement` set, `time` in ms), `write()` builds escaped line protocol, and `getLast()`/`getRange()` translate to `SELECT * FROM /.*/ WHERE "topic" = '…'` queries — merging per-series results, since `LIMIT` applies per series in InfluxQL, and normalising to the same oldest-first `{ ts, val }` shape as v2 (value from the `value` field, falling back to the first data column).

**Tests:** `test/unit/influx.test.js` — mode detection, line-protocol escaping, v1 write/query transport against a mocked `fetch`, InfluxQL escaping, and the sandbox v1 paths (topic escaping, per-series merge/trim/sort, no-config no-ops). **Docs:** `doc/sandbox-api.md` (both config variants, InfluxQL example), `doc/cli.md` (config keys per version).

**Original item:** support classic InfluxDB 1.x setups where the connection is configured with just host/port, database name, and username/password (no token/org/bucket). Config should accept the v1-style options and use the v1 API (`/write?db=…`, `/query` with InfluxQL) when configured that way. The Config UI section should offer both variants, e.g. a v1/v2 mode switch that shows the matching fields.
