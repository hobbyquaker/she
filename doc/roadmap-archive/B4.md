# B4 — Matter tab attribute-action buttons (Step ▲/▼) do nothing ✅ fixed
*Archived roadmap item — Bugs. Open items: [../../ROADMAP.md](../../ROADMAP.md) · Index: [README.md](README.md)*

**Reported (08/2026).** The Step ▲ / Step ▼ buttons on the `currentLevel` attribute row in the Matter tab did nothing when clicked.

**Root cause — two stacked defects:**

1. The buttons sent `levelControl.stepWithOnOff` with `{ stepMode, stepSize, transitionTime }` but without the mandatory `optionsMask`/`optionsOverride` bitmap fields, so every invocation failed TLV validation (`ValidationMandatoryFieldMissingError`) — the same failure class scripts hit with `she.matter.send`. This half was already fixed by the `sendCommand` boilerplate-defaulting (commit `1b9a719`): the backend now fills the bitmaps, so the button payloads validate.
2. `sendCmd()` in `Matter.svelte` swallowed command errors into `console.error`, and the page's `error` state only renders when *no* device is selected — so failures while viewing a device were invisible by construction. The buttons looked dead instead of failing loudly.

**Fix (this item):** command failures now surface in a dismissible error banner (`cmdError`) at the top of the device detail view, labeled with the failing `cluster.command` and the backend's error message.

**Relates:** the `she.matter.send` boilerplate-defaulting (documented in `doc/sandbox-api.md`), [B3](B3.md) ✅ (live attribute updates after commissioning).
