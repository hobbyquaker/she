# I5 — Services: remote hosts over SSH ✅ implemented
*Archived roadmap item — Integrations. Open items: [../../ROADMAP.md](../../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Implemented (she 1.23.0).** Adapter hosts other than the she host are managed through the same `she-servicectl` helper over SSH. What shipped:

- **Driver** — `createSshDriver()` in [src/lib/services-host.js](../../src/lib/services-host.js): `ssh <user>@<host> sudo -n /usr/local/bin/she-servicectl …` with shell-quoted arguments and stdin pass-through (env files, install options), `spawn` for the journal follower, `run` for the helper deploy, `upload` via `scp`; exit 255 → `SSH_FAILED`, "command not found" → `HELPER_MISSING`. `ssh-deploy.js` now exports its `sshArgs`/`scpArgs`/`sshTarget` builders with a configurable default identity (the broker code keeps its own default) and `generateKeypair()` takes a comment.
- **API** ([src/web/services-api.js](../../src/web/services-api.js)) — ssh entries of `services.hosts[]` get the ssh driver (default identity `<data-dir>/ssh/services_id_ed25519`); `GET/POST /she/services/ssh/pubkey|keygen`, `POST /hosts/:host/test`, `POST /hosts/:host/helper/deploy` (scp the shipped helper to the SSH user's home, try `sudo -n install`; when sudo refuses, return the two commands for the admin — install + sudoers line — per SV-4), hostname auto-capture into `services.hosts[].hostname` on first successful `list` (SV-14). Helper version check was already part of `list` (`helperOutdated`).
- **Frontend** — Settings → Services: *This host* switch, remote host list editor (name, ssh host, port, user, identity file, hostname), *Generate key* with the public key to copy; Services → Hosts: *Test* on every host, *Deploy helper* on remote hosts with the result / admin instructions, SSH-specific hints.
- **Tests** — fake `ssh`/`scp` fixture (`test/unit/fixtures/fake-ssh.sh`): quoting, stdin, sudo prefix, SSH_FAILED/HELPER_MISSING classification, upload, the routes (hosts + hostname capture, test, deploy with and without sudo).
- **Docs** — [doc/services.md](../services.md) *Remote hosts* section and config table, HTTP API rows, security note on the SSH user and its single sudo rule.

Deviation: the hostname capture writes `config.json` directly from the API (read-modify-write of the `services.hosts` entry) instead of going through the Config page, so it works without a save from the UI.

**Original item:** Second host driver on the generalised `src/lib/ssh-deploy.js`: `services.hosts[]` with the same `ssh` shape as `broker.ssh` (kept separate, SV-7), SSH key generation and host list in the Config section, helper deployment to `/usr/local/bin` with the sudoers line printed for the admin (she never edits sudoers remotely), hostname auto-capture for `info.host` correlation (editable), helper version check on the Hosts tab. Depends on [I4](I4.md).
