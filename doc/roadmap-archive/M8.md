# M8 — Rename Matter devices via context menu ✅ implemented
*Archived roadmap item — MQTT, Matter & Broker. Open items: [../../ROADMAP.md](../../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Implemented (user-requested).** Auto-derived device names like "H606A" are the device's `basicInformation.productName` (shown because the writable user label, `nodeLabel`, is empty). Renaming writes `nodeLabel` — the Matter-standard label, persisted on the device itself — which she already prefers over `productName` everywhere names are displayed or matched.

**Shipped:**

- `controller.js`: generic `setAttribute()` (remote attribute write via `Endpoint.set()`, transactional) and `rename()` (writes `basicInformation.nodeLabel` on endpoint 0, logs, broadcasts the updated device list).
- `POST /she/matter/devices/:nodeId/rename` — validates non-empty, ≤ 32 chars (Matter nodeLabel limit); documented in `doc/http-api.md`.
- Matter tab: right-click context menu on sidebar devices with **Rename…** (InputDialog pre-filled with the current name), **Copy node ID**, and **Unpair…** (reuses the existing confirm flow). After a rename the device list and open detail view refresh.

**Notes:** scripts that address the node by name (`she.matter.send('H606A', …)`) must switch to the new name after renaming — `_findClientNode()` matches `nodeLabel` first; the node id keeps working regardless. Renaming does not affect Apple Home's display name (HomeKit stores its own names outside the device).

**Tests:** `matter-controller.test.js` (nodeLabel write on endpoint 0 + device-list broadcast), `matter-api.test.js` (rename route: trim, 400 on empty/too-long, 404 on unknown node).
