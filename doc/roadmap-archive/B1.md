# B1 — Logs tab stays empty although scripts are logging ✅ fixed
*Archived roadmap item — Bugs. Open items: [../../ROADMAP.md](../../ROADMAP.md) · Index: [README.md](README.md)*

**Reported (08/2026).** Scripts visibly generated log messages, but the Logs tab showed nothing — even for messages logged while the tab was open. The same messages did appear in the per-script log pane in the Scripts tab.

**Root cause.** The Logs tab rendered entries with a keyed each block — `{#each entries.filter(visible) as e (e.ts + e.msg)}`. Log timestamps have millisecond resolution, so two identical messages logged in the same millisecond produce a **duplicate key** — and in Svelte 5 (verified in 5.56.0, `internal/client/dom/blocks/each.js`) a keyed each with duplicate keys **throws in production too** (`each_key_duplicate`; only the error details are dev-only). The throw aborts the each render, and since the duplicate stays in the array, every subsequent render throws again — the list stays permanently empty. The Logs tab shows *all* daemon lines plus the merged `/she/logs/history` backfill, so a same-ms duplicate is practically guaranteed; the per-script pane in the Scripts tab filters to a single script's entries, which happened to contain no duplicates — hence the asymmetry that pinpointed the bug (both panes consume the identical `subscribeLog()` feed from `web/src/lib/ws.ts`).

**Fix.** Duplicate entries are legal in a log stream, so keyed identity is wrong there: the each blocks are now unkeyed (index-based) in all three log panes that used the `ts + msg` key — `web/src/pages/Logs.svelte`, the script log pane in `web/src/pages/Scripts.svelte`, and `web/src/pages/broker/MosquittoLogs.svelte` (the latter two were latent instances of the same bug). Also shipped: `Logs.svelte` now stores the `subscribeLog()` unsubscribe function and calls it via `onDestroy` (previously leaked), and the stale doc comment in `src/web/log-ws.js` (`{ type: 'log', line }`) was corrected to the actual payload `{ level, msg, ts }`.

**Verification:** svelte-check error count unchanged (pre-existing errors only); web dist rebuilt. No automated frontend test — the web app has no component test infra (would need vitest + jsdom; consider under T).
