# A1 — Health check endpoint ✅ implemented
*Archived roadmap item — Architecture, Operations & Security. Open items: [../../ROADMAP.md](../../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Implemented (she 1.37.0).** `GET /she/health` in [src/web/server.js](../../src/web/server.js), fed by a provider registered in [src/index.js](../../src/index.js) next to the existing stats provider.

- **200 / `status: "ok"`** when scripts have started and either no broker is configured or the configured one is connected. **503 / `status: "degraded"`** while the startup gates are still closed (retained MQTT state, Matter controller) or a configured broker is disconnected.
- Body: `{ status, uptime, started, mqtt: "connected"|"disconnected"|"disabled", scripts }`, plus `safeMode: true` in [safe mode](S4.md) and `version` **only for authenticated callers** — an unauthenticated probe gets nothing to fingerprint. `Cache-Control: no-store`.
- **Public** (added to `OPEN_SHE_PATHS`): a Docker `HEALTHCHECK`, an nginx upstream probe or a monitoring agent cannot present a session. The provider is a cheap object literal — no counting, no allocation, safe to poll every few seconds.
- **Decision — safe mode answers 200.** It is a state the user has to reach the web UI to get out of; a probe that drops the daemon from an upstream pool (or restarts the container under an orchestrator) while it lasts would be actively harmful. Alerting on the `safeMode` field is the intended path.
- Used by the image `HEALTHCHECK` added in [A8](A8.md). Docs: [http-api.md](../../doc/http-api.md#get-shehealth). Tests: 8 cases in [test/unit/server.test.js](../../test/unit/server.test.js) (each status transition, public in password mode, version only when authenticated).
