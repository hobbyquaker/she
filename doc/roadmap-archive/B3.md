# B3 — Matter tab shows stale state until reload after freshly pairing a device ✅ fixed
*Archived roadmap item — Bugs. Open items: [../../ROADMAP.md](../../ROADMAP.md) · Index: [README.md](README.md)*

**Reported (08/2026).** After pairing a device, toggling it physically (device button) did not update the state shown in the Matter tab. Reloading the web UI showed the correct state, but the page never live-updated.

**Root cause.** `_broadcastNodeAttributes()` in `src/matter/controller.js` — the function that attaches `<attr>$Changed` listeners and forwards changes as `matter:attr` WS events — was only called from two places: daemon init (for nodes already online) and the node's `online` lifecycle event. The **commissioning path never called it**, and since a freshly commissioned node is already online, the `online` event never fires again — so the new node had zero attribute watchers until the next daemon restart. Page reload appeared to work because `GET /she/matter/devices/:nodeId` reads the live local mirror directly.

**Fix.** `_commissionInner()` now calls `_broadcastNodeAttributes(clientNode, nodeId)` right after wiring the lifecycle events. Additionally, when the watcher setup finds zero watchable attributes (endpoint structure not yet populated at that moment), the per-node guard is released so the next `online` event retries instead of leaving the node permanently unwatched.

**Test:** `matter-controller.test.js` — "commission attaches attribute watchers and broadcasts changes (B3)": commissions a fake node, asserts the `$Changed` listener is registered, simulates a device-side change and asserts the `matter:attr` broadcast.
