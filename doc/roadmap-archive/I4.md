# I4 — Services: xyz2mqtt inventory and local host management ✅ implemented
*Archived roadmap item — Integrations. Open items: [../../ROADMAP.md](../../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Implemented (she 1.22.0).** The optional *Services* feature — Tier 0 (MQTT inventory) plus the local host driver — per the design in [ROADMAP-SERVICES.md](ROADMAP-SERVICES.md) (decisions SV-1…SV-19). What shipped:

- **Backend** — [src/lib/services-inventory.js](../../src/lib/services-inventory.js) (pure: `analyzeServices()` over the state store from retained `<name>/info` + `<name>/connected`, legacy rows, `wipeTopics()` reusing the M10 discovery analysis), [src/lib/npm-registry.js](../../src/lib/npm-registry.js) (24 h cached `latest` lookups, also for I7), [src/lib/services-host.js](../../src/lib/services-host.js) (host-driver interface, local driver `sudo -n she-servicectl …`, journal/env parsing, secret detection), [src/web/services-api.js](../../src/web/services-api.js) mounted at `/she/services` (Tier 0 routes; host routes for list, schema, unit control, logs tail + ref-counted journal followers broadcast as `serviceLog`, env read/write with masking, install/uninstall, update with manual-deploy detection, broker.env). Unit tests: `services-inventory`, `services-api`, `services-host` (fake helper in `test/unit/fixtures/`).
- **Helper** — [service/she-servicectl](../../service/she-servicectl), POSIX sh, argument allow-list, node resolved from the adapter's wrapper (SV-17), install origin registry/manual (SV-16); installed with its sudoers line by `service/install.sh` (= `sudo she --install`).
- **Frontend** — `services.enabled` toggle in Settings (Config.svelte), *Services* nav tab with worst-case dot (App.svelte), [web/src/pages/Services.svelte](../../web/src/pages/Services.svelte) with sub-tabs *Instances* (MQTT ↔ host correlation per SV-14, actions, expandable info), *Hosts* (helper status, adapters with update, broker.env editor), *Add instance* (wizard on `--config-schema`); `services/SchemaForm.svelte` (schema → form, required first, shared MQTT options collapsed, secrets masked), `services/InstanceDetail.svelte` (config, live journal, info drawer).
- **Docs** — [doc/services.md](../services.md), HTTP API section, security section on the helper, README/getting-started notes.
- **Core companion** — mqtt-interfaces-core 0.4.0 (`x-secret`, `mqttInterfaces` in `x-adapter`, README on keyword + field); cul2mqtt 1.1.2 carries keyword and field.

Deviations from the plan: `services.hosts` defaults to the she host when absent, so the host tier works with just the enable switch; SSH host entries are accepted in config and listed as *unsupported* until I5; the helper's `npm origin` uses npm's hidden global lockfile as the registry fingerprint (no `_resolved` in modern npm). The `serviceLog` follower is renewed by the client every 5 min and expires after 10 min without renewal (SV-13 broadcast model).

**Original item:** Optional **Services** feature (default off, `services.enabled` on the Config page, own nav tab) that manages the `xyz2mqtt` adapter instances built on [mqtt-interfaces-core](https://github.com/hobbyquaker/mqtt-interfaces-core). Scope: **Tier 0** — inventory from the retained `+/info` / `+/connected` topics already in the state store (instance, adapter, version, host, uptime, connected 0/1/2; pre-core adapters shown as *legacy* rows), restart and log level over the `maintenance/set/*` topics, npm update badge, wipe-retained for gone instances (reusing the M10 cleanup path), nav dot. **Local host driver** — the privileged POSIX helper `she-servicectl` (argument allow-list, installed with its sudoers line by `she --install`), systemd unit control, journal tail + follow over the log WebSocket (`serviceLog`), env-file editing with a form generated from the adapter's `--config-schema` (secrets masked via `x-secret` / name heuristic), install/uninstall wizard, adapter update with dev-deploy detection, Node resolved from the adapter's wrapper; Hosts sub-tab (local only). Docs: `doc/services.md` plus a security section on the helper. Core-side companion change: `secret: true` → `x-secret` in `configSchema()`.
